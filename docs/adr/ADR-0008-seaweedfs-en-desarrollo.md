# ADR-0008 · SeaweedFS como servidor S3 de desarrollo

- **Estado:** Aceptada · 2026-10-15 · Complementa ADR-0004
- **Contexto:** El contrato inicial usaba MinIO. Las imágenes oficiales `minio/minio` y `minio/mc` ya no se pueden descargar (Docker Hub: *access denied*; `quay.io/minio/minio:latest` no existe). Usar reconstrucciones de terceros (p. ej. `pgsty/minio`) es un riesgo de cadena de suministro para un sistema que guarda documentos legales y datos sensibles.
- **Decisión:** Usar **SeaweedFS** (`chrislusf/seaweedfs`, imagen oficial del proyecto, Apache-2.0, tag fijado `3.97`) con su gateway S3. Servicio `storage`: `weed server -s3 -s3.config` con una identidad generada de `S3_ACCESS_KEY`/`S3_SECRET_KEY`; puerto host 9000 → 8333 para que `S3_PUBLIC_ENDPOINT_URL=http://localhost:9000` no cambie. Servicio `storage-init`: crea el bucket con `weed shell` de forma idempotente. El backend no cambia: `S3FileStorage` (boto3) habla S3.
- **Verificación (15/10/2026):** `put_object`, GET con URL prefirmada, PUT con URL prefirmada (enviando el mismo `Content-Type` firmado), rechazo de credenciales inválidas (`ClientError`) y de acceso anónimo (HTTP 403).
- **Verificación del adaptador `S3FileStorage.presign_put` (POST con política):** subida dentro del límite → 204; subida mayor que `max_bytes` → 400 `EntityTooLarge`; `Content-Type` distinto al firmado → **no se almacena**, pero SeaweedFS responde **307** en lugar de 403. Regla para el frontend: toda respuesta que no sea 2xx en una subida es un fallo.
- **Consecuencias:** (+) Imagen oficial y mantenida; menor consumo de memoria que MinIO. (−) Sin consola web de administración equivalente a la de MinIO; la inspección se hace con `weed shell` o cualquier cliente S3. (!) Las subidas con URL prefirmada deben enviar exactamente el `Content-Type` usado al firmar; el frontend lo fija en el helper de subida.
